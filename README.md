## 데이터 형식

EntryUser에서는 다음과 같은 데이터 형식을 다룹니다.

| 형식      | 경로                 | 저장소 사용 여부 | 주기적 업데이트 |
| ------- | ------------------ | :-------: | :------: |
| **청크형** | `entryuser/files/` |   **O**   |   **O**  |
| 통합형     | `entry-user.json`  |     X     |     X    |
| 간단형     | `data.json`        |     X     |     X    |

현재 저장소에서 실제로 사용되며 주기적으로 업데이트되는 형식은 **청크형**입니다.

통합형과 간단형은 데이터 구조를 설명하기 위한 참고 형식입니다.

---

## 1. 청크형 — `entryuser/files/`

대량의 유저 데이터를 여러 개의 JSON 파일로 나누어 저장하는 형식입니다.

현재 저장소에서 **실제로 사용되며 주기적으로 업데이트되는 데이터 형식**입니다.

### 구조

```text
entryuser/
└── files/
    ├── users_chunk_001.json
    ├── users_chunk_002.json
    ├── users_chunk_003.json
    ├── ...
    └── users_chunk_055.json
```

각 청크 파일은 `users_chunk_NNN.json` 형식의 이름을 사용합니다.

청크 번호는 반드시 연속적일 필요가 없습니다.

예를 들어 다음과 같은 구조도 정상입니다.

```text
entryuser/
└── files/
    ├── users_chunk_001.json
    ├── users_chunk_002.json
    ├── users_chunk_005.json
    └── users_chunk_010.json
```

따라서 데이터를 사용할 때는 실제로 존재하는 `users_chunk_*.json` 파일을 기준으로 처리해야 합니다.

### 데이터 예시

각 청크 파일은 기본적으로 다음과 같은 구조를 사용합니다.

```json
{
  "000000000000000000000000": {
    "id": "000000000000000000000000",
    "nickname": "가상의유저",
    "profileImage": "https://playentry.org/uploads/00/00/000000000000000000000000.png",
    "follower": 100,
    "following": 50,
    "created": "2026-01-01T00:00:00.000Z",
    "lastUpdated": "2026-09-13T10:00:00"
  }
}
```

최상위 객체의 Key는 해당 유저의 고유 ID이며, Value에 유저의 상세 정보가 저장됩니다.

### 데이터 필드

| 필드             | 타입                 | 설명            |
| -------------- | ------------------ | ------------- |
| `id`           | `String`           | 유저의 고유 ID     |
| `nickname`     | `String`           | 유저 닉네임        |
| `profileImage` | `String` / `null`  | 프로필 이미지 URL   |
| `follower`     | `Integer` / `null` | 팔로워 수         |
| `following`    | `Integer` / `null` | 팔로잉 수         |
| `created`      | `String` / `null`  | 계정 생성 날짜      |
| `lastUpdated`  | `String` / `null`  | 마지막 데이터 갱신 시각 |

`id`는 Entry에서 사용하는 24자리 고유 식별자를 기준으로 합니다.

## 2. 통합형 — `entry-user.json`

통합형은 모든 유저 데이터를 하나의 JSON 파일에 저장하는 형식입니다.

현재 저장소에서는 **사용하지 않으며 주기적으로 업데이트되지 않습니다.**

청크형 데이터를 하나의 파일로 합친 경우와 동일한 구조를 사용할 수 있습니다.

```json
{
  "000000000000000000000000": {
    "id": "000000000000000000000000",
    "nickname": "가상의유저",
    "profileImage": "https://playentry.org/uploads/00/00/000000000000000000000000.png",
    "follower": 100,
    "following": 50,
    "created": "2026-01-01T00:00:00.000Z",
    "lastUpdated": "2026-09-13T10:00:00"
  }
}
```

### `null` 값에 대하여

일부 필드는 데이터 수집 당시의 상황에 따라 `null`이 될 수 있습니다.

* 새롭게 발견된 유저의 상세 정보가 아직 조회되지 않은 경우
* 프로필 이미지가 존재하지 않는 경우
* 계정이 삭제되었거나 존재하지 않는 경우
* 특정 정보를 조회할 수 없는 경우

예:

```json
{
  "id": "000000000000000000000000",
  "nickname": "가상의유저",
  "profileImage": null,
  "follower": null,
  "following": null,
  "created": null,
  "lastUpdated": "2026-09-13T10:00:00"
}
```

### 날짜 형식

`created`는 ISO 8601 UTC 형식을 사용합니다.

```text
2026-01-01T00:00:00.000Z
```

`lastUpdated`는 다음 형식을 사용합니다.

```text
YYYY-MM-DDTHH:mm:ss
```

## 3. 간단형 — `data.json`

닉네임과 고유 공개 ID만 저장하는 간단한 형식입니다.

현재 저장소에서는 **사용하지 않으며 주기적으로 업데이트되지 않습니다.**

```json
{
  "닉네임": "고유공개아이디"
}
```

예:

```json
{
  "가상의유저": "000000000000000000000000",
  "테스트유저": "111111111111111111111111"
}
```

Key는 닉네임이고 Value는 해당 유저의 고유 공개 ID입니다.

## 데이터 형식 비교

| 항목          |  청크형  | 통합형 | 간단형 |
| ----------- | :---: | :-: | :-: |
| 저장소에서 사용    | **O** |  X  |  X  |
| 주기적 업데이트    | **O** |  X  |  X  |
| 상세 유저 정보    |   O   |  O  |  X  |
| 프로필 이미지     |   O   |  O  |  X  |
| 팔로워 / 팔로잉   |   O   |  O  |  X  |
| 계정 생성일      |   O   |  O  |  X  |
| 마지막 갱신일     |   O   |  O  |  X  |
| 여러 파일로 분할   |   O   |  X  |  X  |
| 닉네임 → ID 조회 |   가능  |  가능 |  O  |

## 청크형을 통합형으로 합치기

`entryuser/files/`의 `users_chunk_*.json` 파일들을 하나의 `entry-user.json`으로 합칠 수 있습니다.

저장소 루트에 `merge_chunks.py`를 만들고 실행하면 됩니다.

스크립트는 `users_chunk_*.json` 패턴에 해당하는 파일을 자동으로 찾기 때문에 청크 번호가 중간에 빠져 있어도 사용할 수 있습니다.

## 저장소 구조

```text
Entryuser/
├── README.md
├── data.json
├── entry-user.json
└── entryuser/
    └── files/
        ├── users_chunk_001.json
        ├── users_chunk_002.json
        ├── users_chunk_003.json
        ├── ...
        └── users_chunk_055.json
```

이 중 `entryuser/files/`에 저장된 청크 데이터가 현재 저장소에서 실제로 사용되며 주기적으로 업데이트됩니다.

## 주의사항

이 저장소의 데이터는 수집 및 갱신 시점에 따라 실제 Entry의 현재 정보와 차이가 있을 수 있습니다.

특히 다음 정보는 변경될 수 있습니다.

* 닉네임
* 프로필 이미지
* 팔로워 수
* 팔로잉 수
* 계정 상태

따라서 이 저장소의 데이터를 Entry의 실시간 데이터베이스와 동일한 것으로 간주해서는 안 됩니다.

또한 데이터가 주기적으로 업데이트되더라도 모든 정보가 실시간으로 반영되는 것은 아닙니다.
