# EntryUser

엔트리(Entry) 유저 정보를 수집하고 저장하는 저장소입니다.

저장소에서 실제로 사용하는 데이터는 `entryuser/files/`의 청크형 JSON이며, 수집 프로그램이 주기적으로 갱신합니다.

## 데이터 저장 방식

유저 데이터가 커지는 것을 줄이기 위해 JSON 필드명을 축약해서 저장합니다.

- 여러 JSON 파일로 나누어 저장합니다.
- 각 파일은 UTF-8 JSON 객체입니다.
- 파일 하나의 크기는 최대 약 850 KiB를 기준으로 분할합니다.
- JSON은 공백과 들여쓰기 없이 저장해 파일 크기를 줄입니다.
- 청크 번호는 연속적이지 않을 수 있으므로 실제 존재하는 `users_chunk_*.json` 파일을 모두 읽어야 합니다.

## 청크 파일 구조

```text
Entryuser/
└── entryuser/
    └── files/
        ├── users_chunk_001.json
        ├── users_chunk_002.json
        ├── users_chunk_003.json
        └── ...
```

파일명은 `users_chunk_NNN.json` 형식입니다. `NNN`은 청크 번호이며, 데이터 양에 따라 파일 개수는 달라집니다.

## 데이터 형식

최상위 객체의 Key는 유저의 고유 ID입니다. Value에는 축약된 필드명이 사용됩니다.

```json
{
  "000000000000000000000000": {
    "id": "000000000000000000000000",
    "n": "가상의유저",
    "pi": "00/00/000000000000000000000000.png",
    "fr": 100,
    "fg": 50,
    "c": "2026-01-01T00:00:00.000Z",
    "lu": "2026-11-04T10:00:00"
  }
}
```

### 필드 목록

| 저장 키 | 원래 필드명 | 타입 | 설명 |
|:---:|---|---|---|
| `id` | `id` | String | 유저 고유 ID |
| `n` | `nickname` | String | 닉네임 |
| `pi` | `profileImage` | String / null | `/uploads/` 뒤의 이미지 경로 |
| `fr` | `follower` | Integer / null | 팔로워 수 |
| `fg` | `following` | Integer / null | 팔로잉 수 |
| `c` | `created` | String / null | 계정 생성 시각 |
| `lu` | `lastUpdated` | String / null | 마지막 정보 갱신 시각 |

`id`는 최상위 Key와 중복되지만, 개별 유저 객체만 따로 다루는 경우에도 식별할 수 있도록 유지합니다.

### 프로필 이미지 경로

`pi`에는 전체 URL을 반복 저장하지 않고 `/uploads/` 뒤의 경로만 저장합니다.

예를 들어 저장된 값이 다음과 같다면,

```text
00/00/000000000000000000000000.png
```

실제 이미지 주소는 아래 기본 주소와 `pi` 값을 이어 붙여 만들 수 있습니다.

```text
https://playentry.org/uploads/ + pi
```

즉, 전체 주소는 다음과 같습니다.

```text
https://playentry.org/uploads/00/00/000000000000000000000000.png
```

`pi`가 `null`이면 프로필 이미지가 없는 것입니다.

### null 값

아직 상세 정보를 조회하지 않은 신규 유저이거나 해당 정보가 없는 경우 일부 값은 `null`일 수 있습니다.

```json
{
  "id": "000000000000000000000000",
  "n": "가상의유저",
  "pi": null,
  "fr": null,
  "fg": null,
  "c": null,
  "lu": null
}
```

## 호환성

수집 프로그램은 기존의 전체 필드명(`nickname`, `profileImage` 등)으로 저장된 JSON과 새 축약 필드명으로 저장된 JSON을 모두 읽을 수 있습니다. 기존 `pi`에 전체 이미지 URL이 저장되어 있어도 `/uploads/` 뒤의 경로로 자동 변환합니다.

데이터를 저장하면 축약 필드명과 상대 이미지 경로로 다시 기록됩니다. 따라서 기존 청크 파일을 별도로 변환하지 않아도 프로그램 실행 후 저장 과정에서 새 형식으로 전환됩니다.

외부에서 데이터를 사용하는 프로그램은 다음과 같이 축약 키를 기준으로 읽어야 합니다.

| 기존 키 | 새 키 |
|---|---|
| `nickname` | `n` |
| `profileImage` | `pi` |
| `follower` | `fr` |
| `following` | `fg` |
| `created` | `c` |
| `lastUpdated` | `lu` |

## 주의사항

- 데이터는 수집 및 갱신 시점에 따라 Entry의 현재 정보와 다를 수 있습니다.
- 닉네임, 프로필 이미지, 팔로워 및 팔로잉 수, 계정 상태는 변경될 수 있습니다.
- 모든 정보가 실시간으로 반영되는 것은 아닙니다.
- 청크 파일을 읽을 때 파일 번호가 연속적이라고 가정하지 마세요.
